# CoffSip REST API Specification

**Project:** CoffSip — Coffee Shop Menu & Order Management API
**Programme:** BuildLab Stage 1 — Backend Development
**Deliverable:** Week 1, Task 1.1 (API design)
**Technology:** ASP.NET Core 10 Web API, C#, PostgreSQL, Entity Framework Core
**Implementation status:** Specification only; endpoints are not yet implemented.

## 1. Purpose and scope

This document defines the expected HTTP requests, responses, and errors for CoffSip's **MenuItem** API before implementation. Week 1 delivers a **single-shop demonstration** with menu-item CRUD. It does not include authentication, operator ownership, ordering, or payments.

In Week 2, the API will add ASP.NET Core Identity/JWT, a required `OwnerId` relationship, and customer-order functionality. The database model in `docs/data-model.md` and ERD in `docs/erd.png` show the intended end-of-stage design.

- **Base URL (local example):** `https://localhost:{port}`; the port is assigned when the project is created.
- **Resource path:** `/api/menu-items`
- **Data format:** JSON (`Content-Type: application/json` for request bodies).
- **Identifiers:** UUIDs (`Guid` in C#, `uuid` in PostgreSQL).
- **Timestamps:** UTC ISO 8601 strings, e.g. `2026-10-16T10:30:00Z`.
- **Prices:** Decimal amounts (`numeric(12,2)` in PostgreSQL). The demo uses a single configured currency, USD; no currency conversion or payment processing.
- **Authentication:** Not required for the Week 1 demonstration. This is **not production-ready** or suitable for real customer data.

## 2. MenuItem resource

| Field | JSON type | Rules | Sent by client? |
|---|---|---|---|
| `id` | string (UUID) | Unique; generated by server | No |
| `name` | string | Required; 1–120 non-whitespace characters after trimming | Yes |
| `description` | string or null | Optional; at most 500 characters | Yes |
| `category` | string | Required; 1–60 non-whitespace characters after trimming | Yes |
| `price` | number | Required; greater than 0, at most 2 decimal places; fits `numeric(12,2)` | Yes |
| `isAvailable` | boolean | Defaults to `true` when creating; required on full update | Yes |
| `isArchived` | boolean | Generated/managed by server; defaults to `false` | No |
| `createdAt` | string (UTC datetime) | Generated by server | No |
| `updatedAt` | string (UTC datetime) | Generated by server; changes after edits/archive | No |

The Week 1 entity has these **nine fields**. `ownerId` will be added in Week 2, populated from the authenticated operator, and never trusted from a client request.

### General behavior

- Active-menu queries exclude items where `isArchived` is `true`.
- `DELETE` performs a **soft delete**: it archives the item rather than physically removing its database row.
- A non-existent or archived item is treated as not found for `GET` by ID and `PUT`.
- Whitespace-only names/categories and invalid prices are rejected, not silently accepted.
- Responses use camelCase JSON property names.
- Error responses use the **Problem Details** JSON format; validation errors also include an `errors` object. Week 2 will centralize exception and error handling.

## 3. Endpoint overview

| HTTP method | Path | Purpose | Success | Possible errors |
|---|---|---|---|---|
| `POST` | `/api/menu-items` | Create a menu item | `201 Created` | `400 Bad Request` |
| `GET` | `/api/menu-items` | List active menu items | `200 OK` | — |
| `GET` | `/api/menu-items/{id}` | Get one active item | `200 OK` | `400 Bad Request`, `404 Not Found` |
| `PUT` | `/api/menu-items/{id}` | Replace editable item details | `200 OK` | `400 Bad Request`, `404 Not Found` |
| `DELETE` | `/api/menu-items/{id}` | Archive an item | `204 No Content` | `400 Bad Request`, `404 Not Found` |

`{id}` is a UUID in the URL path. An incorrectly formatted ID produces `400`, and a valid but unknown ID produces `404`.

## 4. Detailed endpoint specifications

### 4.1 Create a menu item

**Request:** `POST /api/menu-items`
**Purpose:** Add a new product to the CoffSip menu.
**Request body:** Required.

```json
{
  "name": "mycoffee",
  "description": "sweetcoffee with steamed milk",
  "category": "Coffee",
  "price": 4.50,
  "isAvailable": true
}
```

**Success:** `201 Created`
**Response:** Full created MenuItem as JSON; `Location` header points to `/api/menu-items/{id}`.

```json
{
  "id": "f19e61c2-4008-4558-9508-7c6133f13822",
  "name": "mycoffee",
  "description": "sweetcoffee with steamed milk",
  "category": "Coffee",
  "price": 4.50,
  "isAvailable": true,
  "isArchived": false,
  "createdAt": "2026-10-16T10:30:00Z",
  "updatedAt": "2026-10-16T10:30:00Z"
}
```

**Errors:** `400 Bad Request` for missing/blank name or category, overlong fields, invalid price, invalid boolean, or malformed JSON.

### 4.2 List active menu items

**Request:** `GET /api/menu-items`
**Purpose:** Return all non-archived menu items.
**Request body:** None.
**Success:** `200 OK`.

```json
[
  {
    "id": "f19e61c2-4008-4558-9508-7c6133f13822",
    "name": "mycoffee",
    "description": "sweetcoffee with steamed milk",
    "category": "Coffee",
    "price": 4.50,
    "isAvailable": true,
    "isArchived": false,
    "createdAt": "2026-10-16T10:30:00Z",
    "updatedAt": "2026-10-16T10:30:00Z"
  }
]
```

**Behavior:** Returns `[]` with status `200` when no active products exist. Archived items are excluded. Pagination and filtering are deferred to Week 3.

### 4.3 Get one menu item

**Request:** `GET /api/menu-items/{id}`
**Purpose:** Retrieve one non-archived MenuItem by UUID.
**Request body:** None.
**Success:** `200 OK` with the MenuItem object in section 4.1.

**Errors:**
- `400 Bad Request` if `{id}` is not a valid UUID.
- `404 Not Found` if no item exists for the UUID or the item is archived.

### 4.4 Update a menu item

**Request:** `PUT /api/menu-items/{id}`
**Purpose:** Replace the editable details of an existing non-archived MenuItem.
**Request body:** Required; send the full set of editable fields.

```json
{
  "name": "mycoffee",
  "description": "sweetcoffee with steamed milk",
  "category": "Coffee",
  "price": 5.25,
  "isAvailable": true
}
```

**Success:** `200 OK` with the complete updated MenuItem object (same response fields as section 4.1, but updated values and `updatedAt`).

**Rules:** `id`, `createdAt`, `updatedAt`, `isArchived`, and future `ownerId` cannot be changed through this request. Updating a price does not rewrite historical `OrderItem.UnitPrice` values.

**Errors:**
- `400 Bad Request` for an invalid UUID, invalid fields, or malformed JSON.
- `404 Not Found` when the UUID does not identify an active menu item.

### 4.5 Archive a menu item

**Request:** `DELETE /api/menu-items/{id}`
**Purpose:** Hide the item from the active menu while retaining its database row for historical order references.
**Request body:** None.
**Success:** `204 No Content` with no response body.

**Rules:** Set `isArchived` to `true` and update `updatedAt`. A repeated DELETE for an existing already-archived item also returns `204` (idempotent). The item remains excluded from normal GET results.

**Errors:**
- `400 Bad Request` if `{id}` is not a valid UUID.
- `404 Not Found` if no item with that UUID exists at all.

## 5. Error response format

We will use JSON **Problem Details** instead of leaking implementation details or stack traces.

Example invalid `POST` request with `price` set to `0`:

**HTTP:** `400 Bad Request`
**Content-Type:** `application/problem+json`

```json
{
  "title": "One or more validation errors occurred.",
  "status": 400,
  "errors": {
    "price": ["Price must be greater than zero."]
  }
}
```

Example lookup of a UUID not found in the active menu:

**HTTP:** `404 Not Found`
**Content-Type:** `application/problem+json`

```json
{
  "title": "Menu item not found.",
  "status": 404,
  "detail": "No active menu item matches the supplied ID."
}
```

These are **illustrative contract examples**; implementation should return the documented fields, but may include additional standard Problem Details members such as `type` or `traceId`.

## 6. Design decisions

1. **REST conventions:** Resource-oriented URLs with standard HTTP verbs make the API predictable.
2. **PostgreSQL and EF Core:** The eventual user–menu–order relationships require referential integrity and migrations.
3. **Decimal pricing:** `numeric(12,2)` is used to represent prices accurately; validation rejects non-positive amounts and values exceeding two decimal places.
4. **UUID IDs:** Server-generated identifiers avoid collisions between new records.
5. **Soft delete:** Archiving a menu item preserves references from future order-history records.
6. **Server-controlled fields:** Clients do not specify item IDs, timestamps, archive flags, or ownership.
7. **Incremental development:** Week 1 is an unauthenticated single-shop demonstration; Week 2 adds login, JWT, ownership checks, and Order/OrderItem endpoints.
8. **No real data:** Only fictional operators, products, and orders are used during this stage.

### Menu Pagination

GET /api/menu-items?page=1&pageSize=10

Query parameters:
- page: Default 1, minimum 1, maximum 10000
- pageSize: Default 10, minimum 1, maximum 50

Responses:
- 200 OK: Paginated menu items as a JSON array
- 400 Bad Request: Invalid pagination parameters

### Authentication Rate Limiting

Applies to:
- POST /api/auth/register
- POST /api/auth/login

Limit: 20 requests per minute per client IP.

Responses:
- 429 Too Many Requests: Request limit exceeded
